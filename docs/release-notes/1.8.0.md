# ReStore 1.8.0

ReStore 1.8.0 is the biggest release so far. Backups now protect themselves in the background, can be found and browsed again
(even on a new PC), use a new snapshot format with compression and better encryption, and the command-line tool can be driven
end to end by scripts and AI agents. A full code review also fixed a long list of reliability and security problems. Existing
configurations, state and backups from 1.6 and 1.7 keep working.

## Protection That Runs by Itself

- **Background protection:** the file watcher and scheduler now run as one protection service that starts with the app, keeps running in the tray, and restarts only when relevant settings change.
- **Start with Windows:** a "Run at startup" option (the MSIX startup task) starts ReStore hidden in the tray after sign-in.
- **Pause and resume:** pause protection for 1 hour, until tomorrow or until resumed, from the tray, the Dashboard or `restore pause` / `resume`; a pause now really stops the watcher, the scheduler, `--service` and `run-due`.
- **Locked files no longer break backups:** a file that is open in another program (an Outlook PST, a database) is skipped and reported instead of failing the whole snapshot; the previous version stays restorable.
- **Staleness alerts:** a banner and a notification when a folder has not been backed up successfully for too long.
- **Run reports and Activity page:** every backup, restore, verify, system backup and repair is listed with files, bytes and skipped files with reasons; a status bar shows running operations and the next scheduled run.
- **Actionable notifications:** Windows notifications with Retry now, Back up now, Open log, Unlock and View report.

## Schedules and Backup Window

- **Clock schedules per folder:** next to the existing interval you can now use `daily 02:00`, `weekdays 18:30`, `mon,wed,fri 06:00`, `weekly sun 03:00`, `monthly last 23:00`, `every 6h`, a 5-field cron expression or `off`.
- **Live preview:** Settings and `restore schedule preview "<expression>"` show the next run times before you save; `restore schedule next` shows what runs when, and why not.
- **Missed runs are made up once:** a PC that was off at 02:00 backs up once when it comes back, not repeatedly.
- **Backup window:** choose a time range (for example 22:00–06:00) in which automatic backups may start; outside it, scheduled and watcher-triggered backups, verification and retention wait, and the status bar says "waiting for the backup window". Manual backups always run.
- **Task Scheduler:** `restore schedule install` registers a hidden `\ReStore\run-due` task, so backups happen even when the app is not running.

## Find and Restore Your Files

- **Snapshot browser:** browse and search any snapshot, restore a selection to a folder or to its original location.
- **File version history:** see every distinct version of one file across snapshots.
- **Compare snapshots:** see what was added, removed and changed between two snapshots.
- **Connect to existing backups:** on a new or reinstalled PC, point ReStore at the same storage and adopt the backups it finds, with the original paths mapped to new ones.
- **Repair:** a mark-and-sweep repair removes leftover chunks of interrupted or deleted backups and re-adopts orphaned snapshots (with a dry run first).
- **Restore file details:** with the new format, timestamps, attributes and empty folders are restored too.

## Snapshot Format v3, Compression and Encryption

- **Format v3 (opt-in per repository):** compressed manifests, file metadata, empty folders and a faster chunker (about twice as fast). New and existing repositories stay on v2 until you choose **Upgrade backup format**.
- **Chunk compression:** text and other compressible data is stored compressed; already-compressed files (jpg, zip, ...) are left as they are.
- **Encrypted repositories, done properly:** a repository key file with password key slots, encrypted manifests (no file names visible in the storage), a one-time recovery key, and **Change password** without re-uploading anything.
- **Wrong passwords are caught early:** a mistyped password is rejected before it can become the key for new backups, and before any chunk is downloaded on restore.
- **Key backup:** `restore export-key` / `import-key` keep an offline copy of the key file.

## Retention, Verification and Storage

- **Retention v2:** keep hourly, daily, weekly, monthly and yearly snapshots (GFS), labelled snapshots are always kept, with a preview in Settings and `restore retention --dry-run`; `restore retention apply` runs it on demand.
- **Verify modes and test restore:** quick (existence and size), sample and full verification, plus a test restore of random files into a temporary folder.
- **Storage usage panel:** logical vs stored size, deduplication and compression savings, growth and reclaimable space.
- **Faster transfers:** uploads and downloads run in parallel, chunk existence checks are batched, and uploads stream without temporary files.
- **Real connection test:** Test connection (and `restore probe`) uploads, reads, lists and deletes a small object instead of only checking that a folder exists.
- **S3-compatible services:** a new `serviceUrl` option for S3-compatible endpoints.

## Settings, Exclusions and Credentials

- **Exclusion presets and globs:** presets for developer folders, caches, Office temp files and system files, plus `excludeGlobs` such as `node_modules/`; the backup destination is excluded automatically.
- **Credential vault:** provider secrets are stored protected for your Windows user (`dpapi:`) or read from the environment (`env:NAME`); `restore config protect` converts existing plain secrets.
- **Export and import settings:** move your configuration to another PC without secrets.
- **Safer Settings:** unsaved changes prompt before you leave, `%USERPROFILE%`-style values and unknown keys survive a save, and the log level can be changed live.
- **About page:** version, data folders, crash reports and a redacted "Copy diagnostics".

## System Backup and Restore

- **Preview before applying:** a system restore shows what would change (environment variables, programs, registry keys) and lets you untick rows.
- **Undo points:** the current state is saved before anything changes, and an undo puts it back.
- **Safer restores:** PATH is merged instead of replaced, archived scripts are never executed, registry imports are checked against an allow-list, and programs are installed with `winget` by exact id.
- **Developer tools (opt-in):** Windows Terminal, PowerShell profiles, VS Code settings and extension list, and git config.

## Agent-Ready Command Line

- **Driven by scripts and AI agents:** every command supports `--json` with one result document and a uniform error document, `restore commands --json` describes every command, and `restore agent-guide` prints a guide for AI agents ([docs/agents.md](../agents.md)).
- **Set up without the GUI:** `init`, `config get|set|add-watch|set-storage|set-schedule|schema`, `encryption enable`, `unlock --remember`, `auth gdrive|dropbox`; every edit is validated before it is written and the previous config is kept.
- **Never hangs:** with redirected input or `--non-interactive` the CLI never prompts; it exits `4` when a person is needed (password, sign-in, confirmation) and `5` when another ReStore process is busy (`--wait <seconds>` waits).
- **Health check:** `restore doctor` checks configuration, storage, encryption, sign-ins, schedules, staleness and more, with a fix for every problem.
- **More commands:** `activity`, `usage`, `diagnostics`, `logs`, `share`, `upgrade-format`, `pause`, `resume`, `version`.

## Portable CLI and Updates

- **Portable `restore.exe`:** a single-file command-line tool for x64 and arm64 that needs no installer, administrator rights or certificate: `irm https://github.com/js302/ReStore/releases/latest/download/install.ps1 | iex`.
- **Update checks:** ReStore checks the GitHub releases at most once a day and shows a Dashboard banner (or a one-line CLI hint); `restore update check|install` works from the command line.
- **Verified installs:** downloads are checked against the SHA-256, size and package identity in the release before anything is installed, and never while a backup runs.

## Privacy

- **Anonymous usage statistics:** which features are used, whether they succeed and how long they take; never file names, paths, contents or names of anything. On by default and announced once.
- **Nothing is sent yet:** no collection endpoint is configured in 1.8.0, so events only wait locally; `restore telemetry preview` shows exactly what would be sent.
- **Easy to turn off:** `restore telemetry disable`, Settings, `DO_NOT_TRACK=1` or `RESTORE_TELEMETRY_OPTOUT=1` ([docs/telemetry.md](../telemetry.md)).
- **Crash reports:** scrubbed reports you can review before anything is sent; ask each time (default), always or never.

## Reliability and Security

- **No lost history:** state saves are crash-safe, a damaged state file is never silently replaced, and the state file no longer grows without bound.
- **Concurrency:** the GUI, the scheduler and the CLI coordinate through a repository lock, so they no longer overwrite each other's state or delete chunks a running backup needs.
- **Windows file sharing:** logs no longer lose lines and settings and state no longer fail to save when another program has the file open.
- **Safer restores:** restore refuses to write through a symbolic link or junction planted inside the restore folder; system restore `--plan` masks environment values unless `--reveal` is given.
- **Regional settings:** snapshot ids, retention buckets and logs no longer depend on non-Gregorian calendars or local number formats.
- **Storage providers:** fixed uploads from partial streams (S3, B2, Google Cloud Storage), SFTP folder creation for relative prefixes, SFTP host-key checking, and GitHub large-file handling; every provider now passes a shared conformance test suite.
- **Damaged chunks:** a stored chunk with the wrong size is re-uploaded and counted in the run report.

## Upgrading from 1.7

- Your configuration is migrated once on first start (the previous file is kept under `backups\`); backups and state from 1.6 and 1.7 load as before.
- Backups stay in format v2 until you choose **Upgrade backup format** (`restore upgrade-format`). Older versions of ReStore cannot read v3 snapshots.
- The first backup after the upgrade reads every file once to rebuild its file index; later runs are fast again.
- Protection starts automatically for configurations with watched folders (`protection.autoStart`; set it to `false` to opt out).
- Command-line behaviour changes for scripts:
  - New exit codes `4` (a person is needed) and `5` (repository busy); `run-due` and `--service` without a usable encryption password now exit `4` instead of `1`.
  - Warning and error lines go to stderr instead of stdout; with `--json`, stdout holds only the result document.
  - Redirected input implies `--non-interactive`, so nothing waits for a prompt.
  - A missing snapshot reports the `not_found` error code (the exit code stays `1`); `test-restore --json` puts its error text in `reason`.
  - `system-restore --plan` masks environment values unless `--reveal` is given.
  - `recovery-key` prints the key on stdout even with `--quiet` (the key is shown only once).
  - `repair`, `restore --conflict overwrite` and `system-restore` ask for confirmation; scripts and agents pass `--yes` (without it they exit `4`).
